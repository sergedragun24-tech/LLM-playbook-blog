# LLM Article Playbook

Система приёмки, фактчека и редактуры SEO-статей про LLM и AI-инфраструктуру для корпоративного блога облачного провайдера. Работает в Claude: инструкции проекта, пайплайн по этапам, регламент прогона, каноны с проверенными источниками и Python-линтер для механических проверок.

Автор: Сергей Драгун, технический редактор. Система собрана в 2026 году и использовалась в работе над статьями блога.

## Зачем

Статьи про LLM быстро устаревают и легко обрастают непроверенными цифрами. Плейбук решает три задачи: каждая цифра в статье проверена по первичному источнику, текст соответствует редстандартам блога, а прогон одной статьи укладывается в разумный расход токенов.

## Как устроено

```
CLAUDE.md              инструкции проекта: роль, порядок по умолчанию, правила источников, редстандарты
pipeline/
  pipeline.md          этапы 0–7: вход, соответствие задаче, соответствие блогу, конкуренты, фактчек, скептик, стилевой гейт, финал
  run-regulation.md    регламент прогона в три чата, точки разрыва, пакет на перенос, формат отчётов
canon/                 тематические каноны: проверенные цифры, дословные цитаты, что нельзя писать
style/
  editing-examples.md  пары «плохо / хорошо» на реальных правках, стоп-листы, грамматика
  register-protocol.md как подключается навык регистра и порядок прогона
reference/             эталонные статьи блога (ссылки)
tools/
  lint_article.py      линтер механики текста
```

Прогон статьи идёт в три чата. Первый принимает черновик: прогон линтера, сверка с брифом и блогом, утверждение состава статьи. Второй проверяет факты, уже по утверждённому составу. Третий правит текст только в согласованных местах и повторно прогоняет линтер.

## Решения, которые выросли из практики

Регламент на три чата появился после разбора расхода на одной статье. Один заход по всем этапам съел около трети недельного лимита, из них примерно 260 тыс. токенов ушло на трёх исследовательских агентов. Выяснилось, что агенты проверяли модели, которые потом всё равно убрали из статьи. С тех пор состав статьи утверждается до фактчека.

Разрыв между чатами закреплён правилом после прогона, где три ступени прошли в одном чате. Из 3,25 млн токенов 53% ушло на перечитывание разросшегося контекста, сама проверка стоила единицы процентов. Теперь Claude сам предлагает перенос в новый чат и собирает короткий пакет из пяти строк.

Механические проверки ушли в скрипт после того, как сборка сводки по десяти статьям блога заняла 9% недельного лимита. Длину предложений, ритм, повторы связок и канцелярит считает линтер, модель их глазами не пересчитывает.

Граница пайплайна задана явно: он принимает и правит готовый черновик. Когда по нему начали писать статьи с нуля, качество упало, поэтому написание вынесено в отдельную команду.

## Каноны

Канон собирается при проверке статьи и потом переиспользуется. В нём дословные цитаты первоисточников, проверенные цифры с датой, формулировки, которые опровергаются источником, и список того, чего в источниках нет и додумывать нельзя. Внизу каждого канона блок «Строки для индекса»: короткие строки, по которым следующий прогон находит нужный факт, не открывая канон целиком.

В публичную версию вошли пять канонов: галлюцинации LLM, стоимость LLM API, ландшафт моделей на август 2026, guardrails, ИИ в маркетинге. Цены и версии моделей указаны на дату сборки канона.

## Линтер

```
python tools/lint_article.py статья.md [--full] [--gpu] [--quiet]
```

Считает объём, структуру, среднюю длину предложений и их разброс, долю коротких предложений, частоту подзаголовков, канцелярит на 1000 слов. Ищет повторы связок в соседних абзацах, конструкцию «не X, а Y», безличные зачины, абсолютные обещания, снисходительную рамку, цифры без ссылки, анкоры в одно слово, остатки черновика и формулировки, уже признанные ошибочными. Домен своего сайта задаётся в `SITE_DOMAIN`.

Нормы сняты с опубликованных статей блога. Метрики линтера необходимое условие приёмки, но не достаточное: текст всё равно читается целиком.

## Что не вошло

Рабочая версия репозитория содержит продуктовые каноны компании, сводку по опубликованным статьям блога, индекс канона, журналы решений по статьям и сами черновики. В публичную версию они не включены. Навык регистра `corporate-tech-register`, на который ссылается протокол, хранится на уровне аккаунта Claude и здесь тоже не лежит.
